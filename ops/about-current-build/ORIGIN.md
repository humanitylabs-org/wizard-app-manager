# Immutable build-stamp origin candidate

REUSE: nginx's actual read-only serving bind, the existing exact owner-gated GET route, `git archive COMMIT`, Dockerfile's JSON writer, the pinned Playwright private route transport, and the already loaded default log encoder.

EXTEND: `.gitattributes` + `web/build.json` put the canonical commit into the release archive itself. Docker's writer still overwrites valid image metadata and now removes the inert checkout placeholder on invalid/missing input. No UI feature, Service, daemon, root helper or live publisher is changed.

## One parent-admitted job, not another carrier

`prepare_origin.py --root <fresh-root> --source <isolated-shell-worktree> --commit <pushed-commit> --prior <r14>` captures only tracked public source. It verifies the old seal, captures the current default log encoder without projecting expanded config, and records the actual fixed nginx bind as an observation, not a fixture eligibility pin.

Copy to `/srv/work/ab-origin-<source-prefix>-v1`, run **only copy/hash dependency staging** with `stage_dependencies.py --reuse /srv/work/ab-ee748c90-r14`, copy back the dependency metadata, then seal every prepared input. Submit **one** `origin_qa.py --manifest-sha256 <seal>` job via the parent. Children must not submit it or run native fixtures over SSH.

The job uses real native nginx and Caddy, immutable source archives, fresh synthetic Git commits for the A→B authority proof, and no owner functional endpoints. It proves that moving `current` alone leaves nginx's old stamp and assets together, then a real fixed-bind rebind changes stamp and assets together while Caddy's PID stays unchanged. Missing/invalid origin bytes must be rejected by the unchanged strict consumer with no stale SHA or comparison request. This is a consumer fail-closed guarantee: nginx can return HTTP 200 for a malformed static JSON file; this patch does not pretend stock Caddy parses arbitrary JSON bodies.

Changed route guards and runtime log redaction are rerun natively. Do not inherit or relabel the old 43-check aggregate. The default encoder source remains exact and appears once. Every tracked public static fetch is verified against the immutable archive before browser execution.

Browser cases: desktop **1280×1000**, **Pixel 7** emulation, and explicit dark standalone fallback. Desktop and phone use real Nebula→Grove picker changes without reloading. The fallback uses real production tokens/CSS and the unmodified `box-source.js` renderer with only its registration host supplied by the fixture. Real public request-context methods stay denied; only allowlisted `route.fetch` transports reach the sealed native fixture. Production CSP is retained. Settings opacity is decoded-pixel noise/blank comparison with a positive underlay control; parent must still inspect the screenshots.

## Normal publication and later live acceptance remain separate

Publish the metadata-only source delta through an existing normal publisher after parent review/PR. `git archive` must receive a **commit**, not `COMMIT:web` or a raw tree. A raw-blob integrity guard must expect the canonical generated bytes **only for `web/build.json`**; compare every other tracked file unchanged. Some ad-hoc publishers have that old raw-blob guard. No broad publisher sweep is authorized or implemented. The existing post-commit generator's fixed two-file copy list is not a shared publication seam.

`activate_origin.py check|apply --expected-config-sha256 <fresh-Caddy-CAS>` is parent-only. It requires the source fix at the **actual nginx bind**, matching direct origin bytes, metadata-writer and feature/SDK/skin hashes, the same tested Caddy binary, an unchanged default encoder, and the existing WAM nonblocking lock. It inserts just the exact route import. Apply additionally requires `--parent-reviewed-receipt-sha256` after the parent reads the receipt and screenshots. It uses the existing atomic/CAS/SIGUSR1 helpers and compensates only if its own config is still present. No core/container lifecycle runs. Live About rendering is explicitly still pending after activation.

Unrelated live HEAD movement never invalidates the immutable candidate job. A changed About/SDK/skin closure requires a fresh live browser capture; it does not authorize pretending the old screenshots cover changed UI. Live comparison counts must come from the actual responded SHA and a same-input module proof, not this fixture's earlier snapshot.

The old `prepare.py`/`refresh.py` per-SHA workflows below this source's original README are historical; the sealed r10/r12/r13/r14 packets are unchanged and retain their failed/unrun/stale status.
