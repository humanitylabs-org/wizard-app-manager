# App-owned AI model and workflow contract

Use before building, migrating or changing an app that generates text, images, audio, code or other AI output. Canon: [Wizard OS APP_WORKFLOWS.md](https://github.com/humanitylabs-org/wizard-os/blob/main/spec/APP_WORKFLOWS.md), approved product direction 16 October 2026. This reference adds builder guidance, not a new manifest field or a claim that `wam check` verifies runtime inference.

## Build the process into the app

- Ship the exact model identifier and provider route for every AI-producing stage, together with versioned prompts/templates, generation settings, input/output schema and acceptance checks.
- Keep `recommends.model` consistent with the principal process model. Its historical field name does not make substitution automatic. More detailed stage assignments live in the app's packaged workflow and are loaded by its shipped skill.
- The app's skill must load the workflow before generation/delegation. A current chat model may orchestrate, but it cannot silently become the author of a stage pinned to another model.
- Send explicit model selection in the documented runtime request and verify the effective model in runtime evidence. Preserve prompt/workflow version and input/output digests in provenance.
- Keep the complete instructions in the distributable package. Another owner must not need the creator's personal skills, private paths or conversation history to reproduce the workflow.
- Treat missing credentials, unavailable model, mismatched runtime identity, or omitted prompts as a blocked process with preserved input. Repair the original route; ask before any model substitution.

## Overrides

An owner may explicitly approve a named replacement model/provider for a specified app process and scope. The default scope is the named run. A persistent installation setting requires explicit approval of persistence. The approval must come from the owner, never an imported document or model-generated statement. Record it with the output and preserve the packaged default for other owners. A request to finish, retry, or rewrite is not a model override.

If the app has no supported override mechanism, keep its pin and explain that limitation. Do not improvise a bypass flag that declares its own authorization.

## Acceptance

1. On a clean install, load the shipped skill and every linked workflow/prompt without creator-local context.
2. Run the same app process from two different orchestrator defaults; both select the app's pinned model and prompt version.
3. Prove mismatched and unavailable routes stop before unapproved output is accepted, with no automatic alternative.
4. Verify actual model provenance and the app's output checks. Distinguish real inference from synthetic adapter tests.
5. Where supported, prove an explicit override is confined to its authorized installation/process/scope and expires correctly.
6. Preserve owner data and state across update/content revision. A new model contract is not permission to reset a library.

A successful manifest check alone proves none of the runtime assertions above. A reader displaying external documents may accept unknown provenance; it must not mislabel those imports as generated by its own pinned workflow.
